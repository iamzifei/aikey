# 规则卡

> 本技能内置的判据。每张卡：判据 / 为什么 / 怎么查 / 强度（硬 = 不可商量；实测 = 有数据，换账号要重测；经验 = 用过有效，未量化）。
> 作者环境里 `{vault}` 有对应的规则文件时，**以 vault 为准，本文件为底**；两处不一致先按 vault 做，再回来修这里。

### 一个比例一次排版，不拉伸不硬裁
- 判据：每个比例都在自己的画布上重新安排人物、文字、留白；不把一张成图拉伸或裁切成别的比例。
- 为什么：横图裁成竖图，左右的字先没；竖图拉成横图，人脸变形。两种都会在缩略图里一眼看出来。
- 怎么查：并排看同一套里的几张，人脸比例是否一致、字是否完整。
- 强度：硬

### 每张都喂原始素材
- 判据：生成每一张时都带上原始人物图和背景图，不只拿上一张成图去改。
- 为什么：链式修改会一张比一张偏，做到第四张人已经不像本人。
- 怎么查：把最后一张和原始人物图并排。
- 强度：经验

### 一张图一种语言
- 判据：中文版只有中文，外文版只有外文；两版意思一致，各自说得自然。
- 为什么：双语堆在一张图上，两种观众都要多读一行，缩略图上谁都看不清。
- 怎么查：每张图上数语言种类。
- 强度：经验

### B 站要两张：16:9 和 4:3
- 判据：给 B 站至少交中文 16:9 和中文 4:3 两张，不只交 4:3。
- 为什么：B 站封面编辑器把「个人空间」和「首页推荐」分开裁，一张图同时满足两处常常会切掉标题或人脸。
- 怎么查：两张都在；上传时分别切到两处预览看裁切，同步裁切不合适就分别上传。
- 强度：经验（以当次上传界面为准）

### 长竖版的中心安全区
- 判据：9:16 封面把完整封面字和人脸放进画布正中的 3:4 区域，再往里留边。以 1080×1920 为例，核心区是 y=240 到 y=1680，上下各 240 像素以背景为主。
- 为什么：Instagram 等平台在主页网格里把 9:16 裁成接近 3:4 显示，上下会被切掉。
- 怎么查：把成图按中心 3:4 裁一份预览，字和脸是否完整。
- 强度：经验。这是设计基线，不保证所有客户端都不切。

### 封面字过红线，平台差异照算
- 判据：封面字按家族公约〈三〉六条过；给国内公域平台的版本全套生效。
- 为什么：封面是观众先看到的那一句，违禁词在这里被判的概率和代价都最高。
- 怎么查：按语言版本分别过一遍，报告里写清每版的结论。
- 强度：硬

### 核像素，不核文件名
- 判据：交付前用只读工具读出每张图的实际像素，比例对不上就重做那一张。
- 为什么：图像工具经常不按要求的尺寸出图，文件名是我们自己起的，证明不了任何事。
- 怎么查：`sips -g pixelWidth -g pixelHeight <文件>`，或用 PIL 读。
- 强度：硬

### AI 出中文字两次不对就换路
- 判据：同一张图的中文字生成两次仍有错字、缺字 → 改为生成无字底图，字用 HTML 排版截图叠加。
- 为什么：AI 出图对中文字的稳定性远低于英文，反复抽卡又慢又贵。
- 怎么查：逐字比对封面字原文。
- 强度：经验
